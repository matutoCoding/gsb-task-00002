# 摄影棚排灯

拍摄前在页面上重排灯、支架、背景板、插座与走线，拖动即所见即所得，并实时指出纸上看不出来的现场问题。

## 运行

无需构建，纯原生 ES 模块 + SVG：

```bash
npm start          # 或 python3 -m http.server 8741
# 打开 http://localhost:8741
```

> 直接双击 `index.html` 在部分浏览器下会因 `file://` 的模块限制失败，请用上面的本地服务。

## 测试

```bash
npm test           # Node 单元测试（几何/校验/联动，12 个）
npm run test:smoke # headless Chrome 端到端（拖动、持久化、双标签冲突、60+ 设备性能）
```

## 页面怎么用

- **拖动**：灯/支架/背景板/插座/人物/拍摄区都能拖；选中灯后拖动蓝色圆点可转灯光方向；拍摄区右下角方块可改尺寸。
- **属性**：选中后在左侧改灯类型（主灯/补光/轮廓光）、方向、线长、接哪个插座、插座容量等。
- **确认锁定**：在属性里把某个对象标记为“已确认”，之后不能再拖动（防止试另一套时误改），画布上会出现 ✓。
- **两套摆法**：顶部“＋ 新方案”复制出独立方案，页签切换来回对比；每方案的改动、确认状态各自保存，互不影响。
- **问题清单**：右侧按“问题 / 绕开 / 已处理 / 联动建议”分栏；每条可点选定位到对应对象。
- **导出**：右下“导出方案 JSON”保存全部方案。

## 会被检查出来的问题（只提示，不替你改）

| 类型 | 说明 |
| --- | --- |
| 越墙 `bounds` | 对象或拍摄区被拖出 10×8 m 棚外，给出当前坐标 |
| 占地冲突 `overlap` | 设备之间、设备与人物站位重叠 |
| 线不够长 `cable-short` | 灯到插座直线距离超过该灯线长，报告差多少米 |
| 未接插座 `cable-noconn` | 灯没有供电来源 |
| 插座过载 `overload` | 同一插座接入功率超过其容量，列出明细 |
| 线缆交叉 `cable-cross` | 两条走线相交，给出交点坐标 |
| 没有入口 `entry` | 0.1 m 栅格 BFS 从门洞走不进拍摄区（设备含 12 cm 安全余量），并指出是哪些设备堵的 |
| 占进拍摄区 `inarea` | 设备落在拍摄区内部 |
| 主光照不到人 `key-cover` | 人物不在主灯光锥内 |
| 主光被挡 `key-blocked` | 主灯到人物的光路穿过其他设备 |

问题可以手动标为 **已处理** 或 **暂时绕开**：

- 标记“已处理”后若问题在后续拖动中再次出现，会显示“（又出现了）”，不会假装没事。
- 统计卡片随时显示未处理 / 暂时绕开 / 已处理数量，现场前一眼能看出还缺哪一步。

## 主灯联动

移动或旋转主灯后，“联动建议”栏会给出：

- 补光应挪到人物另一侧约 45°；
- 轮廓光应放到人物身后侧后方；
- 人物站位/朝向要进新的光锥；
- 主灯自身的线是否够接到原插座。

这些**只是建议**：可点“按建议摆放”一键采纳，也可“暂时绕开”；用户已经摆到位时建议自动变为“已按建议调整”。

## 数据与并发

- **刷新恢复**：方案、当前所在页签、网格吸附偏好都存 `localStorage`；刷新后停在刚才那套方案，不回初始状态。
- **多标签页**：用 `BroadcastChannel`（旧浏览器回落到 `storage` 事件）实时同步，顶部显示同时在线的标签数。
- **乐观锁冲突**：每个实体带 `rev`，提交时附带“共同祖先”版本。两个页面在看到彼此之前都改了同一盏灯时，后合并的一方弹出选择：**保留我的版本 / 采用对方版本**，任何一边都不会被静默覆盖。

## 性能

- 拖动只更新被拖对象的 `transform` 和它自己的线/光锥，不触发规则引擎；松手后再异步校验。
- 校验里最贵的入口寻路是 100×80 栅格的 `Uint8Array` BFS；“找堵路设备”只在已经无路时运行，且最多对最靠近门→拍摄区连线的 14 个对象做移除试探。
- 60+ 设备下单次完整校验约 2–3 ms，拖动事件处理无阻塞。
